## 2. Technical Handoff & Invariants ("Next Person Must Know")

* **Canonical Repo Path**: Always build and run from `/home/pi/viewtouch-main/modern` (never the legacy `~/Desktop/viewtouch-main` directory). Pi commands for the owner start with `cd ~/viewtouch-main` and end with `; beep3`.
* **viewtouch.db belongs to ViewTouch**: Live DB `~/.local/share/ViewTouch/ViewTouch/viewtouch.db`. ViewTouch keeps the store in memory and writes it back, so no other program may write to the DB while it runs (changes are lost or overwritten). The label utility opens it read-only (`mode=ro`). Any bulk import (menu, gift cards) must stop ViewTouch, back up the DB, then restart.
* **Branches**: `main` (what the Pi runs), `claude-label-utility` (Bob's working branch; `modern/tools/update_label_utility.sh` on the Pi merges it into `main` and pushes), and upload-only branches written by Pi scripts: `pi-shots` (label utility screenshots), `pi-vt-shots` (ViewTouch screenshots, `capture_vt_screenshots.sh`), `pi-logs` (`push_label_log.sh`). Bob's cloud workspace can't build or run Qt, so anything visual is captured on the Pi and fetched from these branches.
* **QML module loading**: The static `ViewTouch` QML module is built without the QTP0001 policy, so it lives under `qrc:/ViewTouch`, not `qrc:/qt/qml/ViewTouch`; `loadFromModule("ViewTouch", ...)` can't find it. Load screens by file as `main.cpp` (`vtmLoadModuleQml`) and the screenshot test (`loadViewTouchQml` in `tests/test_pos_flow.cpp`) do. `tests/test_pages_ui.cpp` and `tests/test_editor_ui.cpp` still use `loadFromModule` and fail on the Pi.
* **Compilation & SQLite WAL Safety**: The Pi 5 has 4 cores and 8 GB: compile with `-j4` (vt-server does; `VT_JOBS=2 vt-server` to use fewer) with the 2 GB swap file and ccache set up on 2026-11-03. Older advice was `-j1`/`-j2` (OOM with 200 MB swap). Never kill `vtmodern` while SQLite is writing in WAL mode (`viewtouch.db-wal`) without cleaning up `.lock` and `.running` files in `~/.local/share/ViewTouch/ViewTouch/`.
* **Zero-Header-Breakage Persistence**: Custom item attributes (`__retail__`, `__cost__`, `__parent__`, and upcoming `__pour_oz__` / `__abv__`) are stored inside `m.recipe` metadata rather than modifying core C++ struct headers, preventing full-tree recompiles and preserving backward/forward database compatibility.
* **Known Fragile Spots**:
  * `modern/android/AndroidManifest.xml`: `<activity-alias android:name="org.viewtouch.pos.Home">` must retain both `<meta-data android:name="android.app.lib_name".../>` lines or Lenovo tablets crash with `UnsatisfiedLinkError` on cold boot.
  * `modern/tools/install_label_utility.sh`: Never delete `/home/pi/Desktop/*label*.desktop` by wildcard, as it deletes the operator's `Update Label Utility` desktop icon.
  * Retail screen "Gift Cards" button: the page is `gift-card` (singular). Fixed 2026-11-02 in both `modern/seed/pages/retail-entry.json` and `modern/ui/qml/WidgetRetailEntry.qml`, which had `gift-cards`.
  * `vt-directv`: Page jump actions require both `"page"` and `"target"` keys.
