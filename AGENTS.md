# Working in this repository (people and AI agents)

This is the store's ViewTouch fork (`paigeent1/viewtouch`), running on a Raspberry Pi 5 at the store.
Several contributors work on it — the owner, Claude and Gemini — so these rules keep everyone in step.

**Names:** Claude is called **Bob** and Gemini is called **Neil**. Use these names when talking to the owner and in
the development notes (e.g. `### 2026-11-02 10:00 ET — Bob (Claude) — ...`, `— Neil (Gemini) — ...`).

## 1. Log every change (required — commits are blocked without it)
Every commit that changes anything (other than the notes themselves or `modern/CHANGELOG.md`) must add an
entry at the **top** of the Log in **`modern/vt-modern-development-notes.md`** (newest first):

```
### YYYY-MM-DD HH:MM ET — <Bob (Claude) | Neil (Gemini) | name> — <short title>
- **What:** what changed
- **Why:** why it changed
- **Files:** the files touched
- **Commit:** short hash, when known
- **Next person must know:** anything the next person needs (optional)
```

- Time is US Eastern (the store's clock). What, Why and Files are required.
- Fastest way: stage your change, then
  `python3 modern/tools/log_dev_note.py --agent <who> --title "..." --what "..." --why "..." [--next "..."]`
  — it writes the entry in this format and stages it.
- `.githooks/pre-commit` enforces this. Enable it once per clone: `bash modern/tools/setup_dev_hooks.sh`.
- Never hand-edit `modern/CHANGELOG.md`; it is generated by `modern/tools/changelog.py`.

## 2. Git discipline
- **Pull before editing** (`git pull`), so you build on the latest work and don't overwrite someone else's.
- Change files through Git (commit + push), not by copying whole files around (e.g. via Google Drive) —
  copying an older file over a newer one silently undoes other people's work.
- Commit the notes entry together with the change it describes. Push to the `myfork` remote on the Pi.
- Don't delete files by wildcard (e.g. `rm ~/Desktop/*label*`); name the exact files.
- Everyone works on `main` (pull, commit, push). Never force-push or reset it (no `push -f`, no `reset --hard` + push, no `pull -X theirs`):
  it silently deletes other contributors' commits and their notes entries. To undo something, add a new commit
  (`git revert`). If history really must be rewritten (e.g. to purge big files), ask the owner first and re-apply
  everyone else's commits on top.

## 3. Area notes
- Label utility: read `modern/tools/LABEL_UTILITY_NOTES.md` before changing `modern/tools/vt_label_utility.py`
  (bitmap-only printing, read-only on viewtouch.db, launch chain from ViewTouch, templates). Its manual is
  `modern/docs/label-utility/` — update it when screens or buttons change.

## 4. Commands for the owner to paste on the Pi
End every block with `; beep3` (three beeps when finished).
